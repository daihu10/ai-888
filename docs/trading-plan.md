# 交易计划

侧边栏「交易计划」按日期填写，支持保存草稿、编辑和查看历史。直接地址为 `/trading-plan?date=YYYY-MM-DD`，默认日期使用北京时间。

日期、昨天、今天、历史计划和保存集中在页面右上角，滚动填写时仍可操作。「昨天」跳转今天之前的最近交易日，「今天」跳转截至今天的最近交易日，周末、节假日自动跳过，选中按钮高亮。默认北京时间15:10前选择上一交易日，15:10起选择截至今天的最近交易日；明确选择的日期和历史链接保留原日期。桌面端持仓与评分按紧凑行排列，窄屏自动展开为带标签的表单。

- 市场环境：大盘是否在5天线上、是否符合交易模式、最高板个数、涨停板个数、跌停数、市场情绪、核心主流及次主流。跌停数紧跟涨停板个数，手动填写0–10000的整数，可留空；后面提供市场情绪下拉框，选项为强势、震荡、弱势，可留空。两者均随日期保存；旧计划缺失时显示为空，无需迁移。市场情绪为手动记录，不影响模式提醒与综合评分。核心主流和次主流并排显示，输入框宽333px；屏幕宽度不足时换行排列。
- 持仓标的：复用系统股票搜索（代码、名称、拼音首字母），支持多只且禁止重复。点击股票名称或代码调用系统详情面板，可在本计划持仓中前后切换。每只独立填写是否在5/10/20天线上，持仓理由后依次为「明日计划」「是否执行计划」「止损线」。新两栏随日期保存，执行选“否”标红并计入顶部提醒；旧计划默认空白和未选择，不影响综合评分。止损线为窄数字框，离开输入框后保留两位小数，可清空或手动修改。历史文字止损以“原止损说明”保留显示，输入数字或同步有效价格后替换；保存其他字段不会丢失旧说明。
- 明日交易计划：持股执行与目标个股，各有独立的「是否执行」选项；选择「否」时标红并计入顶部模式检查提醒，选择「是」解除对应提醒。文字和选择随当前计划日期保存，不影响三项平均评分。旧计划缺少新选项时显示未选择，无需迁移。
- 操作评分：是否按计划执行、是否持有非5天线上个股、是否持有非20天线上个股；后两项分别记录持股理由和无条件止损条件。三项各为1–10的整数，填齐后自动计算算术平均分，保留一位小数，满分10分。

表单下方的「评分日历」结合市场环境历史记录、系统共享交易日历和当天交易日判断生成，周末、节假日及今天以后的日期不生成按钮，无日期的月份不展示。今天只要确认为交易日，即使尚无市场环境记录或计划，也显示白色日期按钮，可直接点击；不受15:10默认计划日期切换规则影响。月份内按星期列对齐，可横向滚动、展开有日期的月份或查看往年。已保存综合评分≥9为红色「符合模式」，≥5且＜9为蓝色「需要反省」，＜5为黄色「亏钱活该」（例如8.7为蓝色、4.7为黄色）。未保存计划或未填齐评分的交易日显示白色。悬停或键盘聚焦查看日期和分数，方向键跳过休市日期，点击切换计划；未保存修改确认及处理期间禁用行为不变。交易日加载失败可重试；无数据时显示空状态，不用工作日猜测节假日。当天交易日状态未知时明确提示，每分钟自动刷新确认，不改写正在编辑的计划日期。

持仓标题旁提供来源日期与「导入」，默认来源为当前计划日期的前一个自然日，可选择更早日期。从已保存计划读取股票、持仓理由和止损线，合并到当前草稿，已有股票保留当前内容并跳过；新增股票的5/10/20天线判断留空，需按计划日期确认或当天同步。导入不复制市场环境、交易安排和评分，也不保存或改写来源计划。没有持仓时提示改选日期，合并超过100只时整次拒绝。导入期间禁用编辑、保存和日期切换，失败保留当前内容；导入成功后需点击「保存计划」。来源读取复用日期详情 API 和集中查询键，每次点击重新读取最新已保存内容；合并后的价格沿用现有股票集合批量查询。

均线选项可手工确认，也可点击持仓标题旁的「同步」自动回填。仅当天计划可以同步：临时注册列表股票的行情需求，调用系统统一行情刷新一次，再从同一份 enriched 快照读取当天原价和5/10/20日均线。比较使用同口径前复权 `close >= maN`（相等选“是”），展示价格仍为未复权 `raw_close`。行日期及行情时间归属必须均为当天，过期、时间异常或缺失数据不用于回填；某条均线缺失时保留对应勾选并提示。不开启历史日线补齐，不修改自选清单。

点击同步还会将止损线替换为当天5日均线价格（两位小数），之后仍可手动修改。均线先按同一快照的 `ma5 * (raw_close / close)` 换回未复权股价，再四舍五入；无效或缺失均线/价格时保留原止损并提示。同步只回填当前表单，开启自动保存时沿用自动保存逻辑，关闭时需点击「保存计划」。同步期间禁用编辑、保存及日期切换，避免响应覆盖后续输入；失败保留原有填写。正常 SSE 行情刷新只更新价格，不自动改写均线勾选或止损线。切换日期或刷新前有未保存提示；保存失败保留当前表单，版本冲突可保留内容后重新加载。

是/否选项按问题含义标记：市场环境、持仓均线及“是否按照计划执行”选中“否”时，以红底、红框和加粗红字突出；“是否持有非5天线上个股”和“是否持有非20天线上个股”则选中“是”时标红，选“否”解除提醒。页面固定标题栏内、交易铁律右侧汇总不符合模式的项目数量，滚动表单时持续可见；窄屏自动换行。改为符合模式的答案后解除对应标记，切换日期不保留上一日的提醒。此提醒仅用于突出人工选择，不改变保存的答案、评分或限制保存。

持仓并列显示「计划当日价」和「当前价格」：前者跟随选定的计划日期，历史日期读取该日未复权收盘价并标记“收盘”，今天复用当天实时行情；后者始终取系统现有股票行情缓存的最近未复权价格（`raw_close`），展示实际数据日期及实时/最近行情/非实时状态。两列价格不随计划保存。所选日没有数据（含非交易日）显示暂无当日行情，不回退到相邻日期；原始价格缺失时不以复权收盘价替代。历史价格与当前行情分别加载和重试，不影响计划填写与保存。

## 接入与数据契约

基于 commit `a92e7b1a19e9b17b7e585c033b834773f3d6e153`，按 L2 源码扩展接入，使用现有前后端注册机制，不改动主应用与核心路由。

- 前端入口：`frontend/src/custom/trading-plan/extension.tsx`，懒加载 `Page.tsx`。
- 后端入口：`backend/app/custom/trading_plan.py`，注册 `app/api/trading_plan.py`。
- 服务：`backend/app/services/trading_plan.py`，复用 `fs_utils.atomic_write_text` 原子替换，进程内写锁保护读改写。
- 存储：`data/user_data/trading_plans/YYYY-MM-DD.json`，一日一份，`schema_version=1`。文件异常或更高版本拒绝覆盖。
- `GET /api/custom/trading-plan` 返回 `{dates: string[]}`，日期倒序。
- `GET /api/custom/trading-plan/calendar?year=YYYY` 返回 `{year, today, today_is_trading, dates, previous, latest}`。`dates`为指定年截至北京时间今天已确认的交易日，`previous`为今天之前最近交易日，`latest`为截至今天最近交易日，可跨年；无日期为`null`。复用市场环境的mtime缓存、共享交易日历缓存及当天探针，不生成或保存空计划；交易日状态未知为`null`。前端按年份和北京时间日期共享查询缓存60秒，每分钟刷新，和评分缓存独立。
- `GET /api/custom/trading-plan/scores?year=YYYY` 返回 `{year, rows: {date, overall_score}[]}`，日期正序，只读取指定年份已保存计划；未完成评分为`null`，不生成空计划。文件异常返回409，存储读取失败返回503。前端按年份缓存60秒，保存后失效对应年份，重新读取评分。
- `GET /api/custom/trading-plan/quotes?symbols=600000.SH,000001.SZ` 一次读取最多100只股票的缓存，返回 `{rows: {symbol, price, quote_freshness}[]}`，不触发取数、不修改自选。
- `GET /api/custom/trading-plan/prices?date=YYYY-MM-DD&symbols=600000.SH,000001.SZ` 使用仓库批量日线读取指定日的 `raw_close`，返回 `{date, rows: {symbol, price, data_date}[]}`，再次校验行日期，缺数返回空价格，不触发历史下载。
- `POST /api/custom/trading-plan/sync` 提交 `{date, symbols}`（最多100只），返回 `{date, rows}`；每行包含价格、行情时效、`above_ma5/10/20` 可空布尔值、`ma5_price` 可空未复权5日均线价格及 `issues`。历史日期拒绝409；行情不可用、暂停或本轮刷新未取得更新返回503；部分股票缺数返回逐项说明，缺失字段不覆盖原值。临时行情订阅按64只分批注册，统一刷新一次，结束释放。
- 持仓新增 `tomorrow_plan`（最长5000字，默认空字符串）、`plan_followed`（严格布尔或`null`，默认`null`）；导入旧日持仓时两者重置，不复制过去的执行状态。`stop_loss` 继续以字符串保存，兼容历史文字说明。
- `GET /api/custom/trading-plan/{date}` 返回表单、日期、版本 `revision`、北京时间更新时间和只读 `overall_score`；未保存日期返回空草稿。
- `PUT /api/custom/trading-plan/{date}` 提交表单与上次读取的 `revision`（初次保存为 `null`），服务端生成新版本；冲突返回409、输入非法422、磁盘不可读写503，不暴露系统路径。

保存后更新当日详情并失效历史日期列表。切换日期重新读取，编辑期间计划内容不进行自动重连/焦点刷新。价格批量查询使用独立的集中查询键，复用全局 SSE 行情失效，不轮询、不重算指标；行情刷新不改写表单。股票搜索继续使用系统 `instrumentSearch` 与共享查询键。

历史价格缓存以计划日期及股票集合隔离，日线修正事件会使价格查询失效；普通行情 SSE 仅刷新当前价格，避免反复读取历史日线。

后端新增扩展需要重启服务，前端源码需重新构建或由 Vite 加载。侧栏位置遵守用户已保存的菜单布局；未配置时追加在现有页面之后，可在设置中排序。升级时复核扩展注册 v1、股票详情公共入口、共享股票搜索、API 类型与查询键，以及 `QuoteService.refresh()` 新增的 `updated` 布尔返回字段（原有状态字段保持兼容）；旧计划缺少10/20天线字段时默认为未选择，无需迁移。该实现沿用单后端进程部署，未提供跨进程同时写入的文件锁。
